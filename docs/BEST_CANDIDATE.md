## 固定的最终计算路径

```text
原始 test.csv
  -> Spark 清洗与保存的历史特征
  -> 保存的 tokenizer 与 DeBERTa 文本权重
  -> 原始连续评分 q
  -> clip((q - 3*rho)/(1-rho), 1, 5)
  -> 按 sampleSubmission.csv 的 ID 顺序输出
```

rho 固定为 **0.2562270314414046**，配置位于 `configs/best_postprocess.json`。该参数来自校准集中 4,898 条明确星级标题的评分统计，未使用公榜分数拟合。完整估计方法保存在 `scripts/export_noise_candidate.py`。预测阶段加载固定参数，无需再次读取校准标签。

此改进表明固定尺度校正在当前公开子集上有效；不能据此证明数据确实经过了指定随机混合过程，也不能把弱标题提示当作已确认的干净标签。观测标签上的校准 RMSE 为 1.217324，与公榜 0.48537 的评估集合和潜在标注尺度不同，应分别报告。

## 服务器运行

把复现工具包解压至已有项目 `/root/autodl-tmp/5434` 后，在 tmux 中运行：

```bash
cd /root/autodl-tmp/5434
bash scripts/run_best_repro.sh
```

该脚本激活已有 `.venv-server`、Java 17 和离线模型环境，使用 Spark `local[8]`，只运行保存的文本模型并加载固定校正参数。每次新建时间戳输出目录，不重新训练或修改融合选择。

程序执行以下检查：

1. 从原始测试 CSV 重建测试特征。
2. 加载保存的文本检查点，重新生成 10,000 条组件预测。
3. 应用已冻结的 rho，生成当前最佳候选。
4. 核对原纯文本预测文件身份以及最佳提交 SHA-256。
5. 原始 `submission.csv`、`evaluation.json`、`selected_config.json` 保持不变。
6. 如果保存的验证特征和预测可用，使用固定参数审计观测标签上的最终验证 RMSE；不拟合参数或选择检查点。

只有执行模式为 `full_raw_test_inference` 且哈希匹配时，才能声称本次完成了完整最佳管线复现。`--cached-predictions` 仅用于导出逻辑检查，其运行时间不能当作模型推理时间。本地已完成缓存导出与上榜文件的字节一致性核验；新的完整 GPU 复现仍需在服务器执行。

结果文件：

- 主日志：`runs/best_repro.log`。
- 每次独立目录：`runs/best_repro_<UTC 时间戳>/`。
- 可上传的小型结果包：`runs/task2_best_repro_results.zip`。
- `reproduction.json` 中记录实际模式、同步后的完整推理秒数、命令耗时、文件哈希及原工件保护检查。
- 若有验证工件，`observed_validation_metrics.json` 记录原文本及最终校正后的观测标签 RMSE。

脚本会重新生成测试特征、token 缓存和文本组件的测试预测，但保留模型权重、训练/验证划分及原提交文件。结果包只包含预测、配置和检查信息，不复制大模型权重。
