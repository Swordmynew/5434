# 问题 2 报告与展示素材

这是报告编写指南；没有以假设值填充实验结果。服务器训练结束后，运行 `python -m task2 report` 获取实际结果素材，并把它整合进整个项目报告。

## 问题定义与数据分析

预测评论的 1–5 分评分，评价指标为 RMSE。数据源是项目提供的训练、测试和提交样例。说明文本、用户商品关系、结构化字段各自的作用，报告评分分布、空值、重复文本和标签不一致情况。区分观察到的不一致与“随机标签噪声”等尚未证明的解释。

## 自主设计与实现

1. 给出 Spark 清洗、交叉统计、分区缓存、训练和推理的架构。
2. 解释标题优先及正文头尾截断、CLS 与正文池化、五类概率期望评分、MSE 与 CE 联合损失。
3. 推导层级关系模型，说明商品与父商品共享信息、冷启动回退和正则化。
4. 解释五折补集统计，特别是全局先验也排除相应折；给出泄漏测试。
5. 给出单纯形约束融合与 ID 对齐过程。
6. 明确预训练权重与 Spark ML 基线使用了哪些外部实现，哪些部分由本项目开发。

## 实验与讨论

将 `metrics.csv` 中实测数据形成比较表；把 `models/*/epoch_*.json`、`hardware.json`、`timings.jsonl` 形成效率表。部分 epoch 必须标注为部分，不用估算值代替完整 epoch 实测时间。

至少讨论平均分、稀疏文本、文本模型、关系模型与融合。加入去用户、去父商品、去标题的消融，并说明哪些确实执行。分析重复文本与冷启动实体分层结果；分组诊断应单独说明划分方式，不能与主划分混为同一测试分数。

说明预算限制、训练采样、GPU 利用、CSV 多行读取的首次导入开销、Spark 聚合开销与缓存收益。不要把单阶段加速推广成整个训练流程的同等加速。

## 必填提交信息

- 队名、姓名、学号。
- 真实硬件：单服务器、RTX 3090 24 GB、14 vCPU Xeon Gold 6330、60 GB 内存；并记录实际分配线程数。
- 每轮训练时间、离线总时间、全量测试推理时间。
- 实际测试或验证 RMSE、Kaggle 公榜/私榜成绩及对应提交文件。
- 成员贡献表，比例合计 100%；由成员如实填写。
- 参考文献与复现命令。

## 展示建议

整个项目共 5–10 页、约 7 分钟展示，问题 2 可分配其中约 3–4 页：

1. 任务、数据观察与整体架构。
2. 文本评分、用户商品关系、折外统计的核心设计。
3. 模型比较、消融及重复内容分析。
4. 效率结果、3090 预算与结论。

准备回答：为什么优化连续评分而不取最大概率类别，如何防止评分统计泄漏，Spark 承担了什么实际工作，以及多模型带来的准确性收益是否值得推理成本。
